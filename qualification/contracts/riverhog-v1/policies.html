Governing policies

These definitions belong to the current Contract Closure. Audit Mode adds recorded application scopes without changing the definitions.

Compatibility

  • archive · Indexed applications

    A valid v1 archive remains independently recoverable throughout the supported v1 lifetime. Pack construction, ingress checkpointing, and resumable-write strategies are not archive-format compatibility promises.

  • cli · Indexed applications

    Command names, options, exit status, and structured output remain backward compatible throughout v1; prose output is for people.

  • components · Indexed applications

    A supported deployment runs components from one coordinated product version.

  • configuration · Indexed applications

    Accepted v1 configuration remains valid throughout v1 unless an unsafe value must be rejected.

  • durable state · Indexed applications

    Every later v1 release applies each durable-state authority's declared transition rule to state created by every earlier v1 release; this does not promise downgrade support or earlier software reading later state.

  • http api · Indexed applications

    Published v1 HTTP and native lifecycle-event contracts remain backward compatible throughout v1.

  • licensing · Indexed applications

    Each continuing first-party Python distribution and OCI repository published in v1 retains every SPDX license alternative granted when that coordinate first shipped in v1; withdrawing a baseline grant requires a new major version.

  • python api · Indexed applications

    Freeze-protected declared public-module exports, callable signatures, selected constants, enum members and values, and selected public model and dataclass structures remain backward compatible throughout v1.

  • recovery · Indexed applications

    Every later v1 recovery release reads every valid earlier v1 archive and provenance set.

Publication

  • image identity scope · Indexed applications

    Runtime descriptors use OCI ImageID (the image configuration SHA-256 digest). A platform-specific image-manifest digest pins a deployed image; an image-index digest identifies the publication set, including attestations. Nonpublishing qualification records local ImageIDs; publication evidence records platform manifest digests. Per-release identities are not permanent v1 contract constants.

  • platform scope · Indexed applications

    A platform or architecture claim applies only to the exact published image, distribution, or installation form that carries it. Qualification platforms remain evidence unless an external contract independently protects them.

  • role retention · Indexed applications

    Publication creates no new product, API, protocol, provider, or direct-consumption promise. Each publication unit retains its exact release role and links to its existing semantic owners.

Extent principles

  • bounded work · Indexed applications

    Large logical totals cross bounded pages, segments, or restartable work steps; a carrier bound does not redefine the logical total.

  • configuration · Indexed applications

    Hardware- or environment-dependent limits that observably affect accepted work are operator-configurable and source-linked.

  • implementation privacy · Indexed applications

    Buffers, provider mechanics, database layout, and other non-observable implementation extents are not frozen here.

  • logical totals · Indexed applications

    A finite logical total has no product-level semantic maximum unless its owning contract declares one.

  • operational capacity · Indexed applications

    Capacity policy may explicitly reject, defer, or throttle work, but must not silently truncate it or become an undocumented semantic ceiling.
