# Qualification of processing and supplied application integration

This is a non-authoritative [#903](https://github.com/nashspence/riverhog/issues/903) qualification proposal for [#998](https://github.com/nashspence/riverhog/issues/998), under [#994](https://github.com/nashspence/riverhog/issues/994). Audited product source is `codex/964-session-owner@c28eceaa2dfec1b3712135469ba12230e74f5ffa` on [#979](https://github.com/nashspence/riverhog/pull/979). The actual reference validation belongs in [VALIDATION.md](VALIDATION.md); no result here claims that the proposed production cut is already integrated.

The issue, current accepted decisions, [AGENTS.md][policy], [README.md][readme] and executable owner contracts control. Reconcile the separate #995/#996/#997 reference inputs before use. Their models, experiments and historical F1 result are useful input, not evidence that #998's processing, application or remote receiving paths have run with the new executor.

## 1. First useful integration sequence

1. Use the shared #995 policy and #996 Native/#997 publication seam as they become usable on the current integration rail. Do not make #998 wait for unrelated whole-issue completion. Wire one real processing claim through the controller, actual target, exact SDK completion/publication and source-retirement owner. Cheap execution must create no optional recovery stores. Required claim, original input/evidence, external intent/outcome and custody records remain present in `restart` and `adaptive` modes.
2. Replace target progress-callback persistence and the controller's redundant adoption/contact/cursor writes with bounded volatile samples on that same path. Preserve acceptance/running ownership, lease/fence/authorization, cancellation and exact terminal acceptance. A sample or status poll cannot create a recovery promise or drive payload work. Prove independent jobs still progress while one target or receiver is held.
3. Exercise both collection-producing and effect/no-output processing. Add FTP/Gogurt and the supplied application cuts at their actual owners, including original thread/process receiving and source cleanup. Apply the sampler-specific acceptance/readback/receiving contract before declaring Review0's remote timeout path safe. Do not offer a second legacy executor when optional recovery is unavailable.
4. On the same semantic path, demonstrate long/unknown replayable work qualifying for a real optional generation, actual interruption and exact recovery. Indivisible external tools explicitly support input/intent restart and retained completed outputs; they do not acquire a fake midpoint checkpoint or credit from waiting.
5. Carry configuration, protocol/API/client/CLI, application state/current baselines, installed manifests and growth/platform evidence together. Complete the current exact-source integration gates before scoped acceptance. Parent #994 alone owns aggregate completion and permission to resume held #991 work.

## 2. Acceptance matrix at the owning boundary

| Boundary | Required acceptance witness |
| --- | --- |
| Logical workflow budget | One immutable effective policy/root for the accepted work; attempts, phases, controller/SDK/target/Native children cannot mint new allowances. Accept an original with zero optional allowance, then offer separately numbered bounded grants to that same original as useful work becomes eligible; no reparenting or semantic identity change. The parent polls bounded original accounting, opens its local phase gate, sends a permit to its configured receiver and later receives exact costs by readback. No outbound Core callback or new parent service is assumed. Current server/operator resource limits remain local clamps. |
| Useful-time accounting | Credit fresh useful elapsed conservatively once across overlapping children. Test overlapping remote cohorts, repeated reports, unknown/uninstrumented intervals and clock/domain changes. A fresh root whose first long supported replay domain is remote must become eligible before terminal completion through verified bounded accounting prefixes; terminal-only credit cannot satisfy that case. Prefix accounting does not prove process/resource receiving. Idle polling, backoff, provider/tool waits and replay earn no invented credit. Unknown settlement retains liability and suppresses new optional admission, not mandatory work. |
| Core claim and selected sets | Preserve exact claim identity, current worker/permission, sealed input/artifact/plan sets, membership and source revisions. Verify complete canonical row/order installation outside the writer, then select only the same fixed prepared generation under current authorization and revision/fence locks. Pending original sealing retains source dependencies through lease expiry and receiving. Matching counts alone cannot authorize effect or settlement. Lost replies recover the same accepted object; changed parameters conflict. |
| Processing outputs/completion | Preserve the exact nondeterministic observer output, authored journal, target output, selected disposition and completion recording. SDK retries reuse captured preimages after response loss, including when source spools have been released under their actual receipt. Missing mandatory evidence is not a cache miss. |
| Effect/no-output settlement | Retain original effect/request identity before ambiguity and exact accepted result/no-output evidence before source retirement. A timeout or target status cannot stand in for effect reconciliation. A failed/unknown effect does not trigger arbitrary whole-target replay with a new identity. |
| Target/control progress | Thousands of bounded callbacks need not create thousands of JSON/fsync/catalog writes. Polling reads current live sample plus retained required state. Processed counters may regress after restart; resumable counters come only from a selected complete generation. Request, cancellation and terminal result barriers remain durable and independently testable. |
| Observer/tool lifetime | Original consumer/process/descendant/stream owners remain reachable through cancellation, child exit, result validation, close/join and resource receiving. A closed presentation stream or expired lease is insufficient. Keep source and partial output pinned while any original remains unresolved. |
| Review0 sampler | Exact operational invocation is retained before submission; acceptance/result/receive reply loss uses original authenticated readback. Hold the original process across timeout, receive its process/streams and watcher, and establish complete output durability/pins before terminal acceptance. That quiescence releases the execution slot for the next disjoint input group in the same workspace, without waiting for prior result adoption or parent settlement. `:receive` transfers exact output/result ownership to Review0, which retains parent obligations; sampler authority never includes Core settlement. Stable control/workspace incarnations survive process restart, and missing originals never imply nonacceptance. |
| Sampler retained state and private receiving | Concrete protected sampler control root and exclusive owner; explicit retained-state bytes/free-headroom reservations cover metadata, results, transfer records, tombstones and cancellation/receiving. Public authorization revocation stops new execution and result/payload disclosure. The retained original-only receiving proof remains valid for exact quiescence/cost/transfer/retirement, never fresh authority. Workspace retirement compares the full frozen transfer set; late retries return the exact retirement receipt. No age-based original deletion or unbounded pending HTTP waiters. |
| FTP ingress | Accepted spool bytes and exact source/history remain until the required Riverhog receipt covers them. Preserve upload/registration/completion obligations after commit/reply loss. Cancelled `to_thread` coordination must receive the actual pass before closing its API. Close/receive the original primary store before deleting its workspace. |
| Gogurt/listeners | Retain delivery/event/invocation identity, entry into user script and exact terminal disposition. A nonzero/timeout outcome cannot automatically replay arbitrary side effects. Native listener stop, original child/process receiving and ledger release remain distinct; unsupported platform coverage is reported as missing. |
| Event relay | Advance only after the complete page acknowledges; webhook reply loss can repeat original source/event IDs. Cursor commit/reply loss reads the committed cursor. Source failure does not stall independent sources. Successful shutdown requires positive original worker joins. No exactly-once promise is added. |
| Independent witnesses | Changed catalog observation, original statement/nonce/signing or calendar intent and follow position commit atomically. An exactly unchanged empty poll checks fresh generation/serial and makes no write. Accepted signatures/proof revisions survive departure, view reset and lost replies. Current calendar/key/source controls remain effective. Statement bytes and witness scope do not change for recovery policy. |
| Optional generations | Complete consistent generation only after finite admission; no codec/snapshot store on cheap work. Original candidate/receiver survives unknown publication. Count successful selection once; hold distinct reservation/count slots and predecessor dependencies. Fallback does not reset the workflow budget. |
| Cleanup and final result | Report durable user result and fully received/quiescent completion separately. Failed close/join/delete preserves the original and charge. Cleanup is bounded and fairly scheduled without per-file replay cursors or hidden unbounded scans. |
| Authority/state/platform | Startup validates and refuses incompatible populated state. No automatic reset, archive-format change, plaintext storage tier or cached positive authorization. Preserve supported state upgrades and original receiving on each shipped backend/platform. |

The concrete application dispositions and sampler contract are in [APPLICATION_EFFECTS.md](APPLICATION_EFFECTS.md). Shared policy/grant fields and conservative in-flight prefix credit belong to [BUDGET.md](BUDGET.md), not an independently invented application percentage. Existing correct mandatory barriers have explicit no-change dispositions; this does not exempt their integration paths from testing. The new sampler protocol, protected state owner, original-only authentication proof and retained-state capacity are proposed requirements; none is implemented or qualified by the existing sampler fixture baseline.

## 3. Failure windows and deliberate test rebaselines

For each changed boundary, inject failure before acceptance/effect, after effect before durable result, and after durable commit before reply. Distinguish known rollback from unknown outcome. Include changed source/authorization, stale concurrent workers, capacity/disk failure and actual original close/join refusal. Exception injection is useful but is not power-loss or process-death qualification.

| Existing owner/test family | Preserve or explicitly rebaseline |
| --- | --- |
| [`riverhog/tests/test_collection_workflows.py`][workflow-tests] | Exact claims, derivation/effect/no-output plans and settlements, immutable selected membership, current authorization and source-retirement conditions. Private scan/progress cursor traces may change, accepted obligations may not. |
| [`riverhog-client` processing provenance/admission tests][sdk-tests] | Exact source/history selection, bounded Native readers, original preimages, upload-response loss after spool release, and close refusal blocking the next reader/completion. |
| Stove0 controller scheduling/attempt/target status and target-support tests | Preserve required acceptance, lease, fencing and terminal outcomes. Replace callback-equals-durable-write expectations with live processed progress, zero optional persistence for cheap work and exact terminal recovery. Preserve bounded coordination and independent jobs under slow execution. |
| Observer support and concrete tool tests | Retain exact captured observation, process/descendant receiving, cancellation and output ownership. No replacement author/tool call may stand in for an accepted original. Tool-specific restart limits must be explicit. |
| FTP spool/publication/cleanup and Gogurt listener/dispatcher tests | Preserve acknowledged ingress and delivery identity, original worker/resource receiving and source-release ordering. Rebaseline only derived scanning/progress, not failed handoff obligations or entered user-script evidence. |
| [`test_a_riverhog_event_relay.py`][relay-tests] | Preserve complete-page acknowledgement, explicit duplicate deliveries, source independence, nonadvancing-page refusal, schema/secret handling and positive worker shutdown receiving. |
| [Minisign][mini-tests], [OpenTimestamps][ots-tests] and [statement tests][statement-tests] | Keep canonical bytes, independent evidence after view reset/departure, nonce-before-network, bounded response/state acceptance and exact conflict/rollback. No live calendar/signing claims follow from fixture ports. |
| [Review0 target tests][review-tests] and [sampler support tests][sampler-tests] | Preserve plan/descriptor/image/request/result identity, opaque output member IDs, declared complete outputs and workspace confinement. Replace the exact-two-endpoint assertion with the selected invocation/readback/cancel/receive hard cut while retaining its conformance guarantees. |
| Processing/review lifecycle diagnostics and current public parity tests | Keep exact failure reasons and deadlines; late failed children cannot disappear behind parent completion or progress. API/client/CLI and generated operation/configuration schemas must agree on the delivered shape. |

New causal witnesses must include these cases:

- A callback or GET poll produces zero new durability work while an actual accepted/running/terminal transition still persists. Restart loses advisory samples without losing accepted request or outcome. Cached status cannot renew permission or stale-worker authority.
- A witness receives an empty caught-up page with the exact same follow position. It returns after a fresh read-only generation/serial check with zero writer/upsert/commit statements; a concurrent view rebaseline rejects it. A changed page still accepts the same fetched observations/intents/cursor atomically, without a second API fetch.
- A lost claim/plan/result/settlement reply reuses the exact original request, output/evidence and acknowledgement. Repeated callback/receipt delivery is idempotent; same IDs with different commitments conflict.
- An irreversible/user-script effect is entered and then exits nonzero, times out or loses a response. The original remains uncertain; neither automatic scheduler retry nor cold restart creates a new effect.
- FTP cancellation interrupts an await but not its original thread. The original pass remains owned, the API remains open until it returns, and a failed primary-store close prevents dependent directory deletion. Lost registration/manifest commit reply cannot discard source/completion evidence.
- Review0's sampler accepted request or exact terminal result exists while its response is lost. Readback returns that original; timeout does not release shared paths. Interrupt between tool return, complete output-file/directory durability, result selection and target checkpoint adoption. A result manifest cannot outrun required output bytes. A watcher delayed at cancellation cannot write into a retired/reused workspace. Missing original sampler state remains unresolved, not implicit permission to resample.
- Optional eligibility coincides with mandatory completion, has unknown cost, held count/storage pressure, zero count/fraction, overrun debt or an unclean accounting restart. Mandatory effect/receiving continues; optional allowance is not recreated by phases or child processes.
- A root starts at zero useful credit with one still-running long remote Native/planning invocation. Authenticated monotone cumulative accounting prefixes permit a genuine default-eligible candidate before terminal completion. Duplicate prefixes add no credit; changed bytes at the same sequence conflict; old/rolled-back/replayed prefixes cannot raise credit. The parent reads the bounded original phase request, freezes new prefix credit in its own phase gate before sending the exact execution permit to the configured receiver, and unfreezes only after authenticated original cost-prefix readback. Deferred cleanup follows the same permit rule and retains liability while its parent is unavailable. Known overlap is subtracted conservatively, unknown cost suppresses new optional work, and unanchored prefix credit is discarded after crash. None of these receipts releases a live process or substitutes for terminal/resource receiving.
- The zero-allowance original above later accepts an exact numbered grant through the actual public operation contract. Lost offer/start-permit acknowledgements or cost-readback replies retain the same liability and reconcile by original readback. Exercise a non-server parent and prove that no reverse Core callback is required. New grants never replace the immutable root, invocation or policy; a raw attachment or original-only receiving proof cannot authorize a grant, phase-start permit or fresh execution/payload permission.
- Core preparation observes a same-count mutation between pages, during ordinal installation and before final selection. Every candidate retains its starting source revisions; required ordinal installation is idempotent and does not invalidate itself by advancing the semantic revision. Incomplete or conflicting row order is refused despite a matching total count. Lease expiry, source deletion, key revocation and installer close failure cannot lose an original or select stale work. Capability sealing exposes bounded GET status; SDK/Stove0 consumers wait under the original deadline/lease and never mark an unsealed capability active.
- Two Review0 input groups execute sequentially in the same workspace before parent publication. The second begins after the first process/streams are received and outputs pinned while its transfer acknowledgement is held; overlapping output paths and concurrent workspace execution are refused. Result adoption/transfer, parent publication, workspace retirement and physical cleanup remain independent, ordered obligations. Retained-state exhaustion refuses new admission while existing cancellation/receiving still succeeds within reserved headroom.
- Revoke the public sampler credential after acceptance. Original-only receiving can observe quiescence/cost and acknowledge already adopted exact output/result ownership, but cannot submit, allocate, grant, read a full result or disclose output. A lost full-result reply plus revocation retains custody until currently authorized disclosure is available. Reject a forged registration/binding/proof, an unrelated invocation, conflicting transfer and replaced control/workspace incarnation. Restart preserves the allocation incarnation without relaunching a started original. Receiving-key rotation retains original-bound key generations; explicit compromise revocation preserves unresolved custody rather than rebinding it. A lost retirement reply and late per-invocation acknowledgement resolve to the same exact complete retired-workspace receipt, including after detailed record compaction.

For every removed private cursor, preserve the safety counterexample that originally motivated its test and express it at the new consistent frontier. Do not preserve old phase counts merely because a test asserts them. Conversely, do not rewrite expected archival bytes, original observations or accepted external results as a “rebaseline.”

## 6. Integration measurements and required gates

Use the existing processing/lifecycle owners under [`scripts/ci_qualification.py`][qualification] and `make profile`. Compare old, new `restart`, and new default `adaptive` on the same exact input/plan/evidence selection, tool image/version, resource configuration, backend, cache state and completion definition. Measure durable user-visible result and final original receiving/cleanup separately; include actual failed attempts and adverse outcomes. Report normal useful work, policy instrumentation, optional setup/capture/publication/reclamation, restore/revalidation and external wait as distinct quantities. Do not hide remaining work in background cleanup or give tool/provider wait time useful credit.

Use actual call/byte/row/write/hash counters alongside elapsed observations. For matched runs, optional overhead uses the new restart path as comparator; the old implementation is not its denominator. A machine-dependent timing miss is not a product failure or authority to weaken custody. Policy decision, declared growth/resource bounds, evidence integrity and semantic correctness remain enforced requirements. No speedup or hard maximum replay-loss guarantee follows from the policy arithmetic or these small fixtures.

Required final coverage includes:

- Current owner tests and causal negatives for callback/control write amplification, exact claims/evidence/effects and original receiving; declared whole-lifecycle growth witnesses in the repository's existing discovery/qualification machinery, including large admitted input/window/output sets and interrupted cleanup. No duplicate hand-maintained main-branch registry.
- Core SQLite/PostgreSQL fencing and concurrent claim/settlement acceptance; both prepared-primary storage adapters and applicable Linux/macOS/Windows source/resource semantics. A Linux fixture does not qualify Windows or PostgreSQL.
- Actual installed Stove0 processing-admission/e2e/overlap and Review0 delivery lanes, FTP composed ingress, event-relay and witness images, plus Gogurt/native listener and shipped target/observer/sampler paths. Real external calendar/webhook/Bitcoin/provider use remains outside this authorization; use maintained controlled qualification fixtures. GPU tests require their actual qualified runtime and must not be claimed from CPU fixtures.
- Current public contract/operation/configuration parity, protected archival boundary tests, generated schemas, examples, dependency/build/installed manifests and state fixtures. Update sampler protocol tests coherently with the new operations rather than retaining the obsolete synchronous path as fallback.
- Explicit populated-state refusal, supported forward-upgrade data survival and interrupted-upgrade tests. Preserve old original obligations with their owner; new/empty initialization is not a migration of old state. No deletion/reset or fabricated old-process receiving.
- `make lint` and relevant focused tests for integration checkpoints, followed by required exact-final-source and tested-merge-checkout CI under repository policy. Before authoritative main delivery, the current mandatory lint/unit/dist-smoke/build or maintained complete qualification path applies. Skipped/blocked checks stay visible; a green reference suite is not the production gate.

Provider activation, merge, deployment, release synchronization/publication, live external effects and the held #991 campaigns are not authorized by this reference. A scoped #998 completion record must identify the actual integration SHA and executed application evidence without duplicating adjacent #995/#996/#997 or parent acceptance claims.
