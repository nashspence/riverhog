## Growth and measurement conditions

Measure useful verified bytes/objects/journal frames/semantic edges/member associations separately from provider wait and replay. Include mandatory durability, optional setup/capture/promote/restore/validation, failed candidates, compaction and cleanup, live allocated storage, cumulative writes, SQL/provider calls, worker/resource receiving and user-visible receipt latency. Waiting produces no useful credit. A final throughput number excluding expensive deferred receiving/cleanup is incomplete evidence.

Use at least three extents within the owner's actual valid domain. Vary parts, object count and payload bytes independently for transfer; descriptor/journal/member/history fan-out for discovery; path depth only within the sealed hint bound for materialization; active and retained historical original count for receiving/capacity. A provider's actual part limit remains authoritative, and is not silently raised. Include pressure, interrupted final adoption and repeated restart. Keep provider request counts separate from local public pages: the measured S3 fixture already exposes repeated full scans, and that path does not receive a linear-growth pass from this reference.

For optional generations, report one composed accounting root, grants, selected exact coverage, cost reservations, actual useful-work credit and complete tail settlement. Test concurrent branches, parent outage, late receipts, unknown optional cost, zero-count/restart/cheap completion, two usable generations with pinned readers, failed partial generation and bounded GC. A counter saying a frontier exists is not useful resume; terminate the real executor, restore the exact complete generation and verify the same full result with measured avoided replay. The pre-existing #995/#996 references are design input, not these #999 integrated measurements.

The original copy comparison is one current-first pair at each extent; execution scheduling changes query grouping. Report that observation without claiming repeatable speedup. Likewise one omitted SQL COMMIT is not one omitted device sync, and the trie reduces duplicated prefix encoding but does not promise lower runtime. Preserve unfavorable timings and extra SQL counts.
