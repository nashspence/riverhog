# Storage, retrieval and recovery implementation proposal

**Owning issue: [#999](https://github.com/nashspence/riverhog/issues/999). Convention: [#903](https://github.com/nashspence/riverhog/issues/903).** This packet supplies concrete integration input; its tests and publication do not make the proposal an accepted repository decision or complete the issue.

The selected approach removes persistent derived progress only after preserving the original effect, custody and receiving boundaries. Keep completed archive backing and exact provider/output identities. Use one workflow recovery budget and the existing Native generation mechanism. Build derived indexes privately, publish only complete accepted results, and retain every original resource until positively received. The design choices below are settled recommendations; remaining work is named implementation and qualification, not an invitation to choose another storage model during integration.

## Shared invariants that determine the implementation

**Accepted bytes and effects precede advisory progress.** A counter is not a part receipt, a checkpoint is not archive authority, and a recorded status is not proof that an entered worker stopped. The experiments intentionally preserve these boundaries. The filesystem test demonstrates why deleting completed backing would break readability; the copy experiment removes only `_record_copy_progress` writes, keeping all original sessions, accepted metadata and final exact output checks.

**Current authorization is checked where it matters.** Reuse verified immutable facts within their exact source/generation lifetime; never reuse a cached positive permission as a durable fact. Copy/retrieval effect entry, result adoption and content disclosure recheck the appropriate current key/scope/incarnation/retirement fence. Original-only receiving retains its established narrow authority after a public cancellation/revocation, without granting new payload disclosure or execution. Destructive retirement still requires the real current owning challenge and retained-copy obligations.

**No remote work inside a shared writer.** Prepare/hash/scan/probe provider state in admitted private execution. A short writer installs an exact bounded result and checks captured revisions/current fences. Source pins outlive public lease expiry while originals can still use them. The complete-index finalizer is the #997 seam, not a renamed whole-corpus hash under a writer.

**New consent and original receiving are distinct.** An ambiguous restore is never repeated merely because the cursor is missing or the same call ID is supplied. Close the original execution before a conflicting successor; then bind explicit renewed consent to the offered predecessor/policy manifest. HTTP body close, HEAD/part-list absence and a timer are not remote execution proof. Unsupported proof yields visible `reconciling`/capacity retention, not fabricated non-entry.

**Zero optional work is a real path.** Cheap copy/read/verify/planning keeps private state and mandatory natural anchors, with no optional generation allocation or restore infrastructure. Optional promotion for long discovery/transport work consumes #995's one root and #996's complete dependency-consistent generation. Work cannot receive another 120s merely by crossing copy/retrieval/CLI/Native boundaries. [CAPACITY_LIFETIME](CAPACITY_LIFETIME.md) fixes ownership, admission and tail cost.

## First integration slice and subsequent order

**First focused #999 step:** on then-current #979, implement the original copy executor and volatile advisory progress using the existing exact write/result mechanics, with source/destination pins and receiving retained. Run the paired real copy witness and the original-session, lost catalog acceptance, cancellation and completed-ledger tests. Cheap copy must create zero optional checkpoints while producing identical archived bytes/metadata and retaining unknown effects. This is a bounded actual-owner slice; it need not wait for a whole-repository census or completion of all #964.

Continue in these dependency groups, with qualification starting alongside implementation:

1. **Copy/transport ownership.** Add copy-owned control/effect records keyed by the immutable copy original and destination incarnation; use existing typed invocation/receipt mechanics. Arm batches within the existing transfer window, outside provider work. Preserve final completed backing and random state. Fix original stream/worker receiving and activate it on public copy/cancel paths. Retain old public operation receipts separately from active tuple pointers.
2. **Common preparation and retrieval acceptance.** Land the storage protocol/descriptor/HTTP/client/adapter hard cut once, including exact policy binding, typed attention and bounded renewed-consent manifests. Consume it from both copy and retrieval. Make retrieval job+plan+key quota atomic; reuse #998's stable caller intent. Test lost replies before removing old prepare retry paths.
3. **Cache and maintenance.** Replace unmanaged retrieval population with parent-bound managed mechanics, exact writer/cleanup receiving and mandatory quota retention. Activate through actual create/process/content/cancel/sweep routes. Move provider checks outside writers; remove whole-inventory status aggregates in the same public contract cut. Install snapshot-based accounting reconciliation with exact original final receipt.
4. **Discovery and projection.** Keep query-only operations disposable; fix lost-original eviction. Refactor long rebuild through the existing discovery/Native retained owner and shared recovery grant. Install staged output in bounded pages; use #997 prepared completion and current final CAS. Apply the #964 descriptor traversal contract to both Core and standalone recovery owners without importing Core/client into recovery.
5. **Local publication and independent recovery.** Retain exact output/repair intent and original native resources; preserve existing files, parent identity and complete source closure; publish using qualified no-replace primitives and required barriers. Recovery uses its existing output/staging role, with no new persistent plaintext tier or optional-store dependency. Finish installed official-age/native-platform qualification before making the new durability claim.
6. **Public/state cut and combined qualification.** Update owning schemas, clients, CLI, configuration, examples, fixtures and installed consumers; remove superseded per-turn persistence and legacy paths. Preserve protected archive identities and state ownership. Run exact-source checks and the tested merge checkout through the repository's current rail; record scoped adoption in #999 under #903.

These are artifact dependencies, not six serial whole-issue prerequisites. #994's real #997 F1 slice remains the parent starting point, and #1000 qualification begins immediately. Reference adoption is optional; independently reproducing a finding is equally valid. Do not cherry-pick the work packet onto main as documentation.

## Deliberate operational and public cut

Keep the existing shared policy/configuration types. New public execution states distinguish work from unresolved receiving, with exact definitions in the owning documents. Copy's old waiting/checking/copying presentation becomes private advisory phase; the accepted public state stays bounded. Retrieval attention reasons and renewed-consent manifests are typed, not arbitrary failure-string retry decisions. Retirement accept/resume/status returns the same original result after the target copy disappears. Local progress cannot acknowledge durability before publication and receiving evidence exists.

Current pre-v1 schema changes replace the old model together across every maintained consumer; no compatibility aliases, dual writers, legacy resume readers or silent startup migration are selected. Use the repository's explicit state-schema initialization/verification. Drain old work with its old compatible owner when possible, retain ambiguous originals, and refuse opening populated incompatible state with the new executable. New baseline initialization is only for genuinely new/empty allocations. A new runtime cannot delete unresolved operator/application state to pass initialization. Archive bytes, keys, supported future upgrade machinery and protected contracts remain intact.

Physical file/SQLite/PG/provider capacity remains with the actual backing owner. Finite logical charge, actual allocated backing and original receiving slots are separate dimensions. Configure headroom and physical quota; unknown or exhausted capacity refuses new work while preserving originals. No blanket WAL, asynchronous-commit or fsync weakening is selected. Native platform publication failures have explicit retention/refusal behavior; a portable call is not proof of power-loss survival.

## What this branch establishes

The packet contains actual-owner current/proposed experiments, exact source maps, failure witnesses, closed integration decisions and raw evidence. It does **not** contain the full production implementation. Product paths are unchanged. Local counters are not device fsync counts, a synthetic provider client is not a real-provider qualification, and the authenticated Python decrypt substitution used for two recovery orchestration tests is not the official-age installed recovery gate.
