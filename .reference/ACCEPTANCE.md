## Role applicability and important non-applicability

Common ownership/identity/discovery/dependency and meaningful configuration/validation conventions cover all 38 current distributions. HTTP rules apply to hosted endpoints, not pure schema/planning libraries. Daemon bootstrap applies to the selected process role, not every console script in the same image. Native supervision applies to actual native payload launch, not every source file importing subprocess. Operational job rules apply to job owners; database state administration retains its own explicit owner.

All five observers, the three collection-producing targets (Opus, NVENC, Review0), Rclone, and both samplers must participate in the applicable runtime matrix. Review0 is tested as a delegating application, not falsely treated as a native encoder. Departure protocol/client/support are tested without inventing an unshipped daemon. All seven semantic-validator providers and the pure planner/compiler retain exact-vector and dependency/side-effect checks.

## Identity regression precision

Use fixed semantic inputs, selected limits and implementation/descriptor identity when checking that changing lease paths, queue/probe timing or host mounts leaves semantic work commitments invariant. Do not require identical digests after changing a codec, image, selected effect destination, semantic naming rules, exact input bytes or a genuinely committed request limit. Validate every resulting commitment against its owner rather than comparing two mutually wrong implementations.

## Evidence scope

Reference-reader tests prove only this packet's reader and coverage guard. The proposed HTTP patch is not executed evidence. Actual parser/app/ASGI tests do not establish container behavior; a fake native boundary does not establish real encoding; local file/process tests do not establish distributed locking or every failure mode. Built portable host evidence and hardware/native/provider evidence remain separately identified. Required ordinary policy/internal/tooling checks remain required even when they are not product-contract witnesses.

## Stopping rule

Close #965 when the selected supplied-Stove0 conventions and complete finite acceptance above are implemented and qualified on the final source. Specific adjacent whole-repository work remains with its owner. An unresolved selected parity violation cannot be relabeled an intentional difference merely to finish. Conversely, a genuine result-kind/authority distinction is not a reason to force a new API, worker, lock, image, state store or provider into existence.
