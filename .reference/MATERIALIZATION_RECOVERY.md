# Materialization and independent recovery: selected #999 implementation

This is a focused reference against product commit `c28eceaa2dfec1b3712135469ba12230e74f5ffa`. It proposes changes and supplies causal source-owner witnesses; it does not change installed product code, qualify power-loss durability, or close [#999](https://github.com/nashspence/riverhog/issues/999). [#994](https://github.com/nashspence/riverhog/issues/994), the repository [AGENTS.md](../AGENTS.md) and [README.md](../README.md) control. [#998](https://github.com/nashspence/riverhog/issues/998) owns application retrieval intent/attachment, [#997](https://github.com/nashspence/riverhog/issues/997) owns common publication, [#964](https://github.com/nashspence/riverhog/issues/964) owns shared tiny-journal traversal, [#958](https://github.com/nashspence/riverhog/issues/958) owns representation validity/durability/readability/growth, and [#546](https://github.com/nashspence/riverhog/issues/546) retains the installed independent recovery proof. None of this requires the later final-v1 artifact-specific baseline under [#969](https://github.com/nashspence/riverhog/issues/969).

Useful work and optional cost attach to the existing caller's #995/#998 root, with a disjoint grant only if a separately justified optional operation is later admitted. Network/provider waits and time waiting for a subprocess earn no useful-work credit. ### Observed causal gaps

The reference tests call these real owners. They deliberately document current gaps; they are not tests claiming the proposal is installed.

* A pre-existing unowned file under `.<output>.riverhog-recovery/output` is removed by `recover_archive` before it discovers that the archive input is missing. The proposed admission must refuse that namespace intact.
* If `_quarantine` links the edited file and another actor replaces its pathname before `output.unlink()`, the newer entry is deleted without being quarantined. Exclusive move removes that second pathname-based deletion.
* A lost reply after SDK link or whole-recovery rename leaves the exact output visible. An exception cannot authorize replacement or a new semantic attempt. The current complete recovery retry refuses the existing output; the selected original receipt makes the original result reconcilable.
* A mapping failure after `_stage_mapping` opens `selected.sqlite3` bypasses its only close; the outer function has never received that connection. The witness retains and closes the exact leaked owner itself so the test leaves no live connection.
* The download executor receives both actual worker executions before its client-close exception, but the first raised client close prevents later clients from being closed. Worker exit and client receiving are separate facts.

## 3. Collision planning and honest growth bounds

The sealed [`materializationHint` schema](../packages/riverhog-provenance-contracts/src/riverhog_provenance_contracts/schemas/riverhog-provenance-v1-journal-entry.schema.json) already limits depth to 32 and component spelling to 128 characters. These are existing semantic advice bounds, not newly introduced resource caps. With those bounds fixed, current planning is linear in members apart from indexed/sort work. Do not claim an unbounded-depth asymptotic violation. The source still repeats the entire normalized and actual prefix for every accepted component; its bounded-depth copy amplification is avoidable.

The selected trie stores each normalized component once on an edge `(parent_node_id, normalized_component)`, its first actual spelling, an alias-conflict bit, leaf count and child count. Each member retains its complete output spelling/hint exactly once and its leaf node. Normalization is exactly `DestinationRules.equivalent` after existing reversible escaping. It never rewrites the semantic hint or output spelling.

Insertions assign parent IDs before child IDs. A single ascending node pass sets `blocked = parent.blocked OR spelling_alias OR multiple_leaves OR (leaf AND child)`. All members at blocked leaves fall back to their own existing ID layout. This catches distinct leaves beneath case/Unicode directory aliases, duplicate leaves, and file/directory collisions without selecting an arbitrary winner or walking the same subtree for every conflicting ancestor. ID-layout and absent/unrepresentable hints use the disjoint ID namespace directly. Duplicate artifact IDs and malformed hints remain errors.

For `K` accepted components and `N` members, trie nodes are at most `K + 1`; spelling storage is linear in accepted encoded component bytes plus one complete member mapping. SQLite B-tree lookup/update costs are honestly `O((K + N) log(K + N))`; the final output retains sorted artifact order. Resident memory is bounded by admitted SQLite pages, one input/output record and a bounded cursor window. The reference comparator materializes its result tuple only to compare hashes; production must stream it. It does not claim native SQLite page IO is constant or that fewer key bytes automatically means lower wall time.

Use a separate admitted scratch connection. Configure its disposable profile once at creation; no retained generation is selected from it. Full iterator consumption is required before the mapping is complete; an early close cannot authorize a partial plan. A refusal/SQL error discards the whole private candidate after original receiving; restart from exact selected member advice. Do not re-open partially constructed tables as a plan. The current durable `desired_*` state receives the completed exact mapping only at its required acceptance boundary. [`SQLite` documents OFF synchronization for rebuildable scratch](https://www.sqlite.org/pragma.html#pragma_synchronous); that exception does not extend to local custody, publication receipts or archive backing.

## 4. Local retrieval and output protocol

### Original request and accepted mapping

Adopt the #998 local retrieval intent in the existing local SQLite owner. Before the first remote effect, persist original request ID/idempotency key, canonical bounded selection, archive roots, exact member/history bindings, target incarnation, qualified destination-rule identity, mapping hash, restore policy, selected source store, explicit resolved lease, event context and recovery attachment. Persist the original plan/ETag before creating its job. A narrower `restore_policy=never` request is a distinct linked original, not a changed body under the old key. The same consumed plan reconciles to its original job. Current authorization and quota refusal never erase it.

Add physical state on that same intent, not a second journal: bounded selected-file manifest, original transfer namespace/incarnation, expected immutable file identities, per-file publication disposition, quarantine association where applicable, directory-barrier status, remote terminal receipt, and cleanup/accounting pending facts. Bound manifest pages by the existing retrieval batch and physical admission. A completion receipt hashes that exact selection and operation ID. Do not include mutable operational grants in semantic archive identity.

### Minimal safe publication batch

1. Reserve workspace, file/reader/worker and result/cleanup headroom before opening or dispatching. Create private candidates exclusively; a pre-existing unowned file/path is a refusal.
2. Read under the exact remote job/current lease. Verify expected whole identity and consume/receive the original response. Sync each final candidate file after its last write. No thread may still write a candidate selected for publication.
3. Under the actual destination namespace guard, install each file by no-replace publication. On an existing target, preserve it; reuse is allowed only for this original accepted destination binding and exact verified bytes, never because names or bytes alone create new ownership.
4. Sync every changed directory, including newly created ancestor links, bottom-up. Within one bounded accepted batch, one barrier per distinct changed parent is sufficient after all its eligible links. A file whose parent barrier is unresolved is visible but not acknowledged complete. Capture exact native failure/unknown outcome in the original receipt disposition.
5. Persist the exact batch publication receipt in local state. Only then acknowledge the original remote job. Lost acknowledgement uses original remote readback; it does not redownload into or overwrite a published path.
6. Receive remaining original clients/streams, remove only owned transient names, sync required deletion metadata, and settle resource/grant/cleanup obligations. Delete the local job/intent only when its original terminal result and all liabilities have received. Published output is retained independently of a failed cleanup.

Do not impose one durable transaction per downloaded chunk, per hash update or per planner row. Required receipt batches may include several exact output files under one accepted job, but may not mix different requests, mappings, source/lease identities or operator dispositions. Partial success is represented as exact per-file outcomes in that same bounded batch; a mixed batch cannot claim all-or-nothing external files without a whole-directory publication boundary.

### Operator edits and eviction

Sync always refuses a differing existing artifact/history/provenance file. Explicit repair first retains a fresh quarantine identifier and association binding original destination, collection/member, original request and original destination-parent identity. Sync that association and its parent before mutation. Move the existing entry into the unique quarantine slot with the qualified exclusive same-filesystem rename; never implement move as link followed by unlink of a revisitable source pathname. Sync quarantine and original parents, record exact moved-object identity, then allow no-replace publication of replacement. A concurrent new entry at the old name remains intact and blocks replacement. A lost move reply reconciles both names under the original intent, preserving both on ambiguity.

The namespace guard pins no-follow parent identities and rejects a substituted ancestor/reparse point. On platforms offering handle-relative operations, use those retained parent handles. Other admitted platform profiles must supply their equivalent native parent/file-ID guard. A preflight `is_symlink` is not that guard. A type-changing race that cannot be safely resolved leaves the moved object quarantined and refuses further automatic mutation; it never follows or deletes it. In-place edits through an already open operator handle remain edits to the preserved object, not permission to reclaim quarantine.

Eviction remains explicitly confirmed. It first reconciles/cancels the exact original retrievals and receives their workers/readers. It then moves each selected exact file into an operation-owned retirement namespace before deciding reclamation; recheck identity there, retain any differing or concurrently changed entry as operator data, and preserve its association. This avoids a stale verification followed by destructive unlink of a newly replaced path. Only positively owned unchanged entries with settled receiving may be deleted. A partial eviction keeps its exact manifest and retries that original operation; it cannot remove a desired-collection row while unresolved children remain.

An exclusive move does not prove that an operator's already-open writable handle stopped. If the admitted native profile cannot exclude non-owner writers to the exact retired object, keep that object and its eviction charged/pending and report the retained bytes. A rehash followed by unlink, a timeout, or the earlier blanket `--confirm` is not positive writer closure. Reclamation then requires either the qualified exclusive writer-closure proof or a **new explicit operator disposition naming that exact retained operation and object** and accepting its deletion despite possible local edits. This manual path applies only to the operator's local materialized/quarantined data; it never overrides original source/custody receiving, a sealed Core effect, provider uncertainty, or unrelated object ownership. Pending eviction seals new automatic publication for that selected local mapping until the original disposition settles.

## 5. Independent recovery workspace and final receipt

### Admission and replay

Validate archive selection and the destination parent before destructive work. Admit one output-scoped native writer guard, original operation UUID and source selection. The exact guard name is `.riverhog-recovery-<destination-key>.intent`, where `destination-key` is the domain-separated SHA-256 of canonical parent identity plus output basename. Create it exclusively with private access, retain its native lock through the operation, write its immutable accepted record, and sync its parent before dependent effects. A restart opens only this exact guard, verifies its current format/ownership/binding and obtains the original native lock; unknown contents refuse intact. No stale-PID replacement or lock timeout grants authority.

Exclusively create a **fresh** private workspace `.riverhog-recovery-<operation-uuid>` beneath the same output parent. Fixed-length opaque names avoid extending an already maximum-length output basename. The accepted record format is `riverhog-local-recovery-operation/v1`; it binds state revision, operation ID, original parent identity, requested output basename, selected archive root/ciphertext pins, metadata pins/expectations, layout/rules, original workspace identity, selected resource/byte grants and cleanup obligation. No key or passphrase enters it. `prepared.json` inside that exact workspace is written once before publication to bind the final receipt hash; the accepted record is never truncated/replaced while being used as a native lock. The shared physical admission retains this owner record in its bounded original allocation set and accounts every unresolved operation, not only the newest one. Restart follows exact owned records, never arbitrary user subtrees.

A fixed path or a successful `mkdir(exist_ok=True)` is not proof of ownership. An existing old scratch tree without the exact current operation record is preserved and refused. A valid incomplete original may restart from archive after its actual process/reader/namespace owners are received; its plaintext files and SQL tables are not optional resumable checkpoints. An unknown child, lost constructor or ambiguous namespace operation keeps the original allocation charged and blocks reclamation. Capacity refusal does not authorize deletion. A new explicitly accepted output operation uses a separate namespace and budget; it never silently adopts the old one.

After a process crash, a stale PID or released application lock does not prove an external child is stopped. An operation lacking actual child/pipe receiving remains retained and cleanup pending; safe admission of independent new work is limited by the remaining physical/resource grant. This is a concrete refusal/retention disposition, not automatic orphan deletion after a timeout. Normal execution records/receives the actual process before final namespace publication.

### Four selected contents and publication

Preserve current order and checks: trusted recovery descriptor and ciphertext root; exact archive manifest/provenance identity; selected description and tag head; complete journal set and foreign/fork closure; member history descriptor, record pages/source proofs, exact primary anchor and selected history extent; every pack/segment part and final artifact-set commitment; exact collision-resolved mapping and complete coverage. Recheck mutable selected metadata ciphertext pins before final publication. Selected-copy freshness is not a claim of globally newest metadata.

Build `recovery-operation.json` alongside `recovery.json` in the private completed tree. Its format is `riverhog-local-recovery-publication/v1`; it binds the original operation/request, immutable manifest/metadata/mapping hashes, selected output-tree inventory commitment and original staging identity. The inventory covers every semantic output file plus `recovery.json`, sorted by canonical JSON bytes of its exact relative-component array. Its SHA-256 input starts with `riverhog-local-output-inventory/v1\n`, followed by canonical objects with keys `components` (string array), `bytes` (exact nonnegative decimal string), and `sha256`, each followed by a newline. It excludes `recovery-operation.json` itself, avoiding a hash cycle; `prepared.json` separately pins that receipt's exact bytes/hash before rename. The receipt is bounded at 64 KiB, while the inventory is streamed through the disposable index. It contains no secret or grant of archive authority. Add the schema/reader in the recovery package and register the output authority in `cli.py::_CLI_RESULT_CONTRACT` in the same hard cut; old completed output directories remain readable user data and are never silently rewritten or adopted. Exact same-operation retry verifies this receipt and the selected output facts before returning the original result; full byte revalidation is charged as real linear work, not claimed constant-time metadata readback. Missing/mismatched/edited output or an unowned pre-existing directory is preserved and refused.

Sync all final files after their last write, including the operation receipt, mapping, metadata, shared history and exact primary sidecars. Sync private directories bottom-up, perform exclusive whole-directory publication, then the destination-parent barrier. Only then mark the original local effect complete. A rename/parent-sync lost reply may leave a complete visible directory; retain the original intent, inspect that exact result and finish required barriers. Do not remove the directory or fabricate a new attempt. Cleanup failure cannot change an already established publication to incomplete; it keeps a separate cleanup obligation and reserved capacity.

The complete output receives the final operation receipt. The external scratch root may retire only after all scratch owners and deletion effects receive; its cleanup-pending control record remains if they do not. The immutable output guard remains as a charged compact original for the output allocation's lifetime, with its lock released between invocations. Same-operation reconciliation requires that original guard plus the exact output receipt; a merely well-formed user-editable output receipt cannot create prior ownership. Explicit retirement of the output allocation, after its result/receiving obligations settle, may retire the guard; its subsequent absence restores ordinary existing-destination refusal rather than automatic adoption. This transfers a bounded immutable result, not a hidden server database dependency. A new recovery from archive plus keys requires no previous operation record; it can target a fresh admitted output even when all prior optional stores are absent.

### Native platform choice

Keep Linux `renameat2(RENAME_NOREPLACE)` and Darwin `renamex_np(RENAME_EXCL)` as the selected directory no-clobber primitives, with retained parent handles and qualified directory barriers. For Windows, use the native Unicode same-volume no-replace move with `MOVEFILE_WRITE_THROUGH`, no replace/copy-across-volume/delayed-reboot flags, plus the admitted native handle/file-ID guard. [Microsoft documents the move flags and their scope](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw). That documentation and a successful syscall do not replace native filesystem/power-loss qualification.

There is no fallback to overwrite, plain replace, cross-filesystem copy-and-delete, or a no-op barrier. A runtime outside the qualified platform/filesystem profile refuses durable-publication admission before effects. An entered effect with unknown completion stays owned and unacknowledged. The current `retained_resource` Windows CRT regular-file profile is not a directory-handle/durability implementation; the new native publication owner must carry that original handle capability explicitly. Keep independent recovery's native helper owner local and SDK's file helper in its SDK owner; do not introduce Core/client dependencies into recovery merely to share application code.

## 6. Physical state, decryption and receiving

### Disposable SQL and explicit capacity

`artifacts.sqlite3`, `journals.sqlite3`, `selected.sqlite3`, collision tables and prepared descriptor indexes are reconstructible from exact archive inputs. Use the existing `sqlite_admission.SqliteConnectionScope`: reserve the original constructor before filesystem effects, configure its immutable disposable profile after the actual connection is retained, and keep its cursors/operations through actual close. None of these databases becomes a recovery selection. A transaction may remain open while the same connection consumes its complete derived result; commit only if required by SQLite visibility/schema mechanics, without durable semantics. Close/error discard needs no repair of disposable data. Retained local intent/receipt databases keep their separate durable profile.

Use the packet's shared physical admission with explicit positive `retained_state_max_bytes` and `retained_state_min_free_bytes`, file/directory/connection/cursor/worker limits and next mandatory-result/receive headroom. The caller owns the deployment values; there is no new default archive-size ceiling. Charge staging, SQL/index overhead, directory entries, final output under construction, quarantine, unresolved originals and deletion liability. A filesystem quota is a separate hard physical boundary. Startup reconstructs bounded exact accounting from owned manifests; it does not scan arbitrary user trees or create a per-step quota journal.

### Plaintext and peak storage

The only durable plaintext selected here is the user's explicitly requested recovered/local output and preserved operator edits. Existing private temporary volume/artifact/history staging remains operation-owned disposable work, not a cross-operation cache, shared dedup store, exporter side channel or retained recovery generation. Keys remain in existing protected input/memory/pipe handling; neither SQLite, receipts, logs nor exception text receives them.

Do not let the official decrypt child write unbounded plaintext before checking `read_bounded`. Change the existing age adapter to read stdout through a bounded owner-controlled stream; admit the exact expected plaintext extent before dispatch, count each chunk before writing, and refuse an overrun. Feed age's stdin from the **original retained no-follow ciphertext handle**, not a path that age reopens after an earlier hash check. Verify expected ciphertext extent/part commitments while feeding that original, and require both complete input verification and successful full decrypt before output adoption. A source replacement or in-place change cannot turn a preflight path hash into proof for different bytes. Metadata uses its contract bound; authenticated volume/segment descriptors provide payload bounds. Keep bounded diagnostics, receive stderr concurrently, require success for the entire input, then receive input-feed worker, process and all pipes. On overrun/cancellation, request stop and receive the actual child; unknown exit retains its resources. [The official age interface supports stdin/stdout and success only after full input processing](https://github.com/FiloSottile/age/blob/main/doc/age.1.ronn). Partial authenticated plaintext is still not a complete output.

One temporary decrypted volume is allowed at a time under admitted bytes. After its verified artifact writes are complete, remove it only after actual readers/processes receive. Final artifact identities are verified and synced once after their last segment. Because workspace and output share an admitted filesystem, link those sealed private files into the final private layout without a second payload copy. On a profile lacking qualified hardlinks, use the current exact bounded copy only after reserving the additional destination bytes; do not silently overdraw storage. Reject an unsupported no-clobber mechanism before publication. Any file left by failure is private, owned, charged, and never a restart checkpoint.

For payload total `B` and largest currently admitted volume `V`, the selected hardlink path requires `B + V` payload storage before publication, plus independently measured metadata/SQL/quarantine and safety headroom. The copy fallback can approach `2B + V`. These are explicit accounting terms, not fabricated measured peaks or permission to omit allocator/filesystem overhead. Large archives are supported by sufficient configured resources and streaming; no policy fraction makes their required final output optional.

### Exact receiving order

Stop new work; receive started worker/child execution and stream consumption; receive result readers, iterators and borrows; receive cursor/blob/connection owners; receive file handles; then remove exact owned candidate names and directories; finally settle caller grants/accounting/root retirement. Output publication may precede independent scratch cleanup, but the latter remains charged. A failed close must not short-circuit receiving of unrelated already-quiescent owners or drop the list containing the failed original.

Reserve each `SqliteConnectionScope` and [`retained_resource.Group`](../packages/retained-resource/src/retained_resource/__init__.py) entry before construction/acquisition. The existing [`sqlite_admission`](../packages/sqlite-admission/src/sqlite_admission/__init__.py) protocols explicitly preserve unreturned construction and original cursor/blob receiving. Recovery may depend on these neutral packages; it must not borrow an application implementation. A containing object cannot declare cleanup complete because its returned connection variable was never assigned. Replace `ignore_errors=True` and swallowed cleanup errors as outcome sources with explicit received/pending state. Preserve the original exception alongside cleanup failures.

## 7. Shared prepared-reader dependency

The exact current Core reference is [`provenance_archive_read.py::CanonicalProvenanceArchiveReader.prepared`](../riverhog/src/riverhog_core/provenance_archive_read.py) with [`provenance_metadata_index.py::ProvenanceMetadataIndex`](../riverhog/src/riverhog_core/provenance_metadata_index.py). [DISCOVERY_INDEXES.md §4](DISCOVERY_INDEXES.md#4-read-only-and-original-receiving-contracts) owns the shared prepared-reader disposition. Standalone recovery currently has a separate reader; importing Core would violate its independent packaging boundary.

Implement the same prepared contract in recovery's existing `_provenance_reader.py`: one complete root/descriptor/terminal verification pass, selective journal/kind descriptor records in an admitted disposable disk index, exact contiguous journal metadata and segment hashes, then query-only same-connection reads. `recover_archive` prepares once and supplies that exact prepared owner to headers, ranges, bindings and history construction. Per-journal iteration reads only its indexed descriptors plus selected payload. No accepted read may use a prefix that has not yet passed terminal commitment verification. No persisted index rebuild occurs during a read-only verification command.

Parity fixtures must run the same malformed/root-swapped/overlap/missing-terminal/segment-corrupt cases through Core and recovery readers. A generation/authorization/source-pin mismatch discards the private derived index, never repairs authority. Receiving the original prepared reader precedes connection close and scratch deletion. This is the #964 dependency required for tiny-journal growth; the collision trie does not solve repeated archive traversal.
