## Locked branch workflow

The final workflow uses repository-pinned Python/uv and `uv --locked --all-packages
--group dev`, applies this exact manifest in the checkout, runs scoped Ruff and
source typing, then the same maintained test cohort on native Linux/macOS. Its
artifacts record reference SHA, patch-manifest digest, applied file hashes,
runtime, complete recursive growth samples, identity links, status and elapsed
execution. All before/after file hashes are checked again after execution.

Do not infer success from this description. The owning issue records the actually
observed final run, failures/retries, counts and artifact digests. A failed,
pending, skipped or ancestor job is not a pass for the delivered reference.
The workflow is a patch experiment, not a clean unmodified product checkout and
not PR tested-merge qualification. That source relationship is intentional.

## Not claimed

No new archive authority, operational activation, provider qualification, memory
ceiling, absolute scheduling latency or complete retirement lifecycle acceptance
is established. Backend SQL/path/lock/OS costs, logging sink and finalizer latency
remain distinct from logical primitive counts. Unknown close witnesses use test-
only compiled seams, not actual kernel-error injection. Process exit disposes
test resources, never substitutes for in-process receiving. Large-member and
128-file qualification remain #964 work. Product integration must consume the
proposal explicitly and run the normal final-source/tested-merge gates.
