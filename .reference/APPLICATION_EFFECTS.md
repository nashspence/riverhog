# Supplied application effects and exact receiving

This is proposed, non-authoritative integration input for [#998](https://github.com/nashspence/riverhog/issues/998) under [#994](https://github.com/nashspence/riverhog/issues/994) and the [#903 convention](https://github.com/nashspence/riverhog/issues/903). Product source is unchanged at `c28eceaa2dfec1b3712135469ba12230e74f5ffa`. The owning issue and current integration decisions control. This document covers event relay, independent witnesses and Review0; the shared controller, ordinary targets/tools and ingress owners are specified separately in this handoff.

## 1. Selected boundaries

| Owner | Retain and why | Selected change or no-change disposition |
| --- | --- | --- |
| Event relay | Source-qualified event identity and whole-page cursor after every delivery acknowledges. Losing the cursor may redeliver; advancing it before an undelivered event loses the event. | Keep the existing page transaction and duplicate semantics. No optional checkpoint store or extra per-event delivery ledger. Make shutdown positively receive every original source worker. |
| Minisign witness | Exact canonical statement, source/view-qualified observation, signing obligation, original accepted signature and key identity. A later catalog view or newly generated signature is not the original evidence. | Keep changed-page observation/intents/cursor and signature acceptance atomic. Suppress the redundant write for an exactly unchanged empty poll. Signing is a bounded local tool operation with restart before acceptance, not a resumable mid-tool computation. |
| OpenTimestamps witness | Exact statement, once-generated nonce, submission/upgrade commitments, operator-selected calendar identity and every accepted proof revision. A new nonce changes the original commitment. | Keep durable intent before network and exact job-version CAS after one exchange; suppress only unchanged empty catalog polls. Retain accepted proofs through departure/reset. Keep retry/allowlist safety state; do not label it optional computation progress. |
| Witness statement library | Canonical immutable collection identity bytes. Mutable description/tags and replay policy do not belong in that statement. | No format or identity change. Keep strict canonical parsing and source binding. |
| Review0 | Sealed plan/descriptor/inputs, original sampler request/result, output bytes and exact publication/completion evidence. Re-running a codec may produce a different result. | Keep these natural mandatory anchors; use the shared volatile progress cut. Add the sampler-specific original invocation/receiving protocol below before treating a timeout as retryable execution. |

These dispositions are based on the actual delegates, rather than whether a method or field is named `progress`, `checkpoint` or `step`. No supplied witness becomes archive authority, and no webhook acknowledgement proves archival custody. [Repository policy][policy] and [README][readme] keep those boundaries separate.

## 2. Event relay: retain page delivery semantics

[`EventRelay.relay_source_once`][relay] fetches a bounded `EventPage`, validates forward progress, maps each event to a CloudEvents document and posts it. Only after the complete page succeeds does `CursorState.advance` commit the new cursor. The outbound `id` remains the original native event ID; `source` includes the configured source name. Existing tests deliberately observe repeated delivery of the same event after a later event in the page fails.

Keep this design. A webhook may accept a request whose reply is lost. Retry sends the same event identity/payload, and a failed page may repeat its already accepted prefix. The receiver must apply its own duplicate handling if it needs it; the relay does not promise exactly-once external effects. Never skip a failed event or advance the cursor merely because the request was sent. A cursor commit with lost reply is resolved by reading the same source's durable cursor, not by allocating replacement event identities. An expired/unavailable source cursor remains an explicit source error; replay policy does not authorize silently resetting it to zero.

This page cursor is an external-delivery acknowledgement boundary already grouped across up to the configured `batch_size`. Increasing persistence spacing independently of delivery pages would change duplicate exposure and replay requirements. This reference selects **no additional grouping and no optional recovery persistence**. Keep `batch_size`, request timeout, poll interval, source configuration and secret-file ownership with this application. Idle polls and network waits earn no useful checkpoint credit. Keep secret-free failure diagnostics and source isolation.

The concrete lifetime correction is in `run`: the current interrupt path sets `stop`, then uses bounded `thread.join(timeout=...)` without checking that each thread stopped. Non-daemon threads are not a returned receiving result. Preserve the original thread and HTTP client until the worker actually exits; use bounded join observations to keep shutdown status responsive, and report `stopped`/return successful runtime completion only after all original joins are received. A deadline leaves shutdown pending; it does not close a client still used by its worker or authorize replacement delivery. There is no need for a durable shutdown microcursor. Test an original delivery held beyond the join observation interval, independent source progress and eventual original return.

The relay state schema is unchanged by this disposition. Its explicit state command and startup validation remain. Do not rebuild or erase its source cursors merely because archive content exists elsewhere. [Relay schema][relay-schema] · [Maintained delivery tests][relay-tests]

## 3. Independent witnesses: accepted evidence is the recovery anchor

### Common catalog following and statement identity

Both stores fetch through `CatalogFollower` outside the writer, then atomically commit observations, new statement obligations and the matching follow position. Generation/serial comparison rejects a stale fetched proposal. Equal-revision conflicting observations roll back both cursor and evidence. An explicit view rebaseline creates a new view generation and preserves previous observations and witness evidence. Source/view changes are not permission to rewrite old evidence. [Minisign store][mini-store] · [OpenTimestamps store][ots-store]

Keep this bounded transaction for a page that changes observations or follow position. The cursor alone cannot certify observations that were not accepted with it. The initial catalog checkpoint also binds the source/authorization view to be followed; it is not a Native replay snapshot. No per-collection optional cursor is added. Page/network scheduling stays separate from signing/maturation so a catalog outage does not prevent already admitted evidence work.

Remove one concrete unnecessary boundary: both current `ingest_once` implementations call `_save_progress` and increment the serial even when a caught-up page has no observations and `batch.after == before.position`. After the existing authenticated fetch, that exact no-change case performs a fresh read-only generation/serial comparison and returns without entering a writer, updating the serial or committing. A concurrent generation/serial change raises the existing `StaleProposal`. If observations, cursor, through-revision, view, source or reset state change, pass that **same fetched batch** to the existing atomic acceptance path; do not fetch twice or cache an earlier permission. Extract the owner's prepare/accept split for this branch rather than duplicating catalog semantics. The reference SQL counter witness measures this narrow cut; it does not weaken signing/proof-result persistence.

[`CollectionWitnessStatement`][statement] encodes only its exact source identity, collection ID, immutable archive root and artifact-set identity. Preserve its existing byte encoding and 512-byte parse boundary. New operational policy, sampler invocation or grant fields never enter this statement, archive formats or provenance identities. A witness attests its declared statement/evidence; it neither changes the archive nor substitutes for independent verification.

### Minisign

The existing signer snapshots public-key bytes, checks the private-key file permissions, signs the exact statement using the local subprocess, verifies against that public snapshot, then returns signature bytes and key identity. `WitnessStore.sign_once` persists the accepted signature with an attempts/state CAS. The signer runs outside the SQLite writer. [Signer][mini-signer]

Keep those barriers. A completed signature remains exact evidence after source departure or view reset. A lost database reply is resolved from that statement's accepted row before another signing attempt. If the original transaction is positively absent/rolled back and no signature was accepted or disclosed, rerunning this local-only signing operation on the retained statement is permitted; it is not a claim that fresh signature bytes equal an earlier unaccepted result. Current key selection and verification apply to that new attempt. A stored signed result is never regenerated under a rotated key.

No midpoint checkpoint is supported or proposed for the Minisign process. The existing subprocess call kills/waits its child on timeout; preserve actual process receiving and temporary-file lifetime before returning a retryable tool failure. Keep capacity/error classifications and retry due/attempt state, which bound external-tool retry pressure rather than measure semantic computation. This focused evidence uses a signer fixture; real Minisign binary/platform/key-rotation tests remain separate qualification.

### OpenTimestamps

[`proof.prepare`][ots-proof] creates a job from an exact statement digest and a caller-generated 32-byte nonce. `_observe` stores that job in the same transaction as the observation and cursor, before any calendar exchange. `proof.step` performs at most one selected submit/upgrade exchange, merges a bounded validated response with prior evidence and checks the serialized-state capacity. `mature_once` CAS-compares both previous serialized job and version, then stores any new proof-history row and current job together.

Keep this protocol and its current batching granularity. Unknown calendar delivery retries the **same operation, calendar and commitment**, never a new nonce. A submit retry may return different calendar evidence; only the exact response actually accepted by the versioned transaction becomes the recorded revision. A known rejected or unaccepted response is not retrospectively claimed as retained proof. An accepted revision cannot be erased by a later timeout, catalog departure, changed visibility or view rebaseline. After an ambiguous commit, read the retained job/proof revision before another request. A competing CAS loser cannot overwrite the winner or report its own different response as accepted.

Maintain the exact operator calendar allowlist on every exchange, no redirects, bounded raw responses, current serialized proof/node/depth/work limits and typed retry failures. A proof-supplied URL cannot enlarge authority. Retain due/attempt decisions and permanent-blocked outcomes; removing them would reset network pressure or retry an operator-blocked operation after restart. These are mandatory operational decisions, not optional Native checkpoints. [Network adapter][ots-network]

Bitcoin verification remains a separately requested bounded read against the operator-selected node, with its existing distinction between unavailable chain observations and invalid proof. Do not cache a positive verification result as permanent current-chain authority. No real calendar or Bitcoin RPC is invoked by this reference. No database synchronization mode is weakened.

## 4. Review0: exact remote execution before workspace release

### Preserve existing semantic evidence

[`ReviewMaterializeTargetService`][review-target] seals the sampler descriptor/image and plan parameters, constructs the exact `SamplerRequest`, validates its result, retains `_SamplerCheckpoint`, verifies output identities and publishes through the shared collection owner. Its output member ID binds the plan and output key; its execution preimage binds the exact sampler result set and output identities. Preserve those bytes and matching checks.

The retained sampler result is **mandatory original tool evidence**, not an optional record that can be dropped in `restart` mode. The completed output and collection receipt are natural anchors. Missing retained output bytes while a result is selected is an explicit custody failure unless an exact already accepted publication receipt covers that output; do not silently run the sampler again under the old result identity. Review0 inherits the shared target's volatile progress design, but that does not alter its accepted request/output/completion checkpoints.

Close the output ordering window as part of this cut. Current code selects `_SamplerCheckpoint` before the per-output publication path calls [`TargetOutputCheckpoint.retain`][output-checkpoint], which synchronizes the original output file and its directories. After positively receiving the sampler process, verify and pin the complete selected output set under the existing [declared protected workspace][workspace]; establish its qualified file/directory durability before selecting a terminal result that depends on those bytes. Review0 must adopt matching output restart records before discarding input or accepting the sampler-result checkpoint. This remains the same admitted application workspace, not a new Core plaintext tier or a second archive. Memory-backed protection does not turn a file synchronization into host/power-loss survival; retain truthful backend failure limits and refuse missing mandatory bytes.

Keep plan traversal and output bookkeeping private. Index canonical windows once by input/output key within admitted memory, or use owner-private scratch for larger admitted plans; avoid scanning the entire window list for each artifact/output. Replace per-output `_verify_output_set` whole-directory rescans with one bounded inventory per completed, exclusively owned sampler invocation and point identity checks for its outputs. Audit the complete selected output set before final acceptance. Do not omit undeclared files or create an archive-size limit to avoid the traversal. Canonical summary/result-set encoding stays identical; stream its construction when it exceeds admitted memory.

### Current missing receiving seam

The current [`ReviewSamplerClient`][sampler-client] calls terminal synchronous `POST /v1/sample`. [`SamplerHttpBinding`][sampler-binding] serializes execution but retains no request/result readback identity. A client timeout is therefore not a proof that the server's original tool stopped. `_sample` also signals its cancellation-watcher thread without joining it, while outer failure cleanup may release/unlink the shared workspace/input.

The server's existing supervised tool owner can receive its own process; it cannot transmit that fact through an absent/lost HTTP response. This is a concrete change requirement, not a claim that the passing fixture qualified remote cancellation.

### Selected sampler-specific operational contract

Hard-cut the sampler HTTP contract, client, bindings, concrete samplers, Review0 and conformance/installed examples together. Preserve `SamplerRequest`, `SamplerResult` and their semantic digests; place operational identity and receiving outside those documents. Keep `GET /v1/sampler`. Replace the synchronous execution path with these exact owner operations:

| Operation | Selected semantics |
| --- | --- |
| `POST /v1/sample` | Accept an envelope containing a stable `invocation_id`, configured Review0 registration identity, original target-request digest, expected control/workspace incarnations and the existing exact `SamplerRequest`. The ID is derived once from the target-request and sampler-request digests and retained locally before submission. Persist exact parameters and workspace/output ownership before dispatch. Return bounded accepted/current status; identical retries reconcile the same invocation, changed parameters conflict. |
| `GET /v1/samples/{invocation_id}` | Authenticated bounded readback of the exact accepted identity, advisory live state and nullable retained terminal receipt. No tool execution, payload hashing, optional checkpoint, wait or synchronization on polling. A missing record or changed service incarnation is unresolved unless the original owner's qualified state proves nonacceptance. |
| `POST /v1/samples/{invocation_id}:cancel` | Select cancellation and bar further execution attempts for that exact original invocation. Return pending until the server's original process and descendants, streams and resources are positively received. Repeated cancellation does not create another execution or claim a timeout stopped it. |
| `POST /v1/samples/{invocation_id}:receive` | Verify the original configured Review0 registration and exact invocation/request/workspace binding, terminal-receipt/output-set digests and Review0's durable output/result ownership-transfer acknowledgement. Accept that acknowledgement idempotently; after complete workspace retirement, return its exact retained retirement receipt instead. The sampler checks its own original and transfer contract; it has no authority to verify or demand a Core/Stove0 parent settlement. |
| `POST /v1/samples/{invocation_id}:receiving` | Original-only proof readback under the retained receiver binding below. Return bounded quiescence, cost and ownership-transfer/retirement facts plus already selected digests, with no result body, output paths, output bytes or renewed execution authority. This read does not join a worker, create a receipt or perform cleanup. |
| `POST /v1/workspaces/{workspace_id}:retire` | Seal that exact workspace incarnation against every new invocation after all original executions are received and every result/output obligation is transferred to Review0. Compare the caller's retained exact invocation/transfer-set count and digest with the same frozen complete set prepared by the sampler owner. Return the same retirement acknowledgement on retry. It does not delete Review0's workspace or certify publication. |

The server binds the original invocation to its exact workspace incarnation and request. **Execution-slot ownership and retained-result ownership are separate.** Review0 currently processes sequential input groups in one workspace before the parent finishes. Once the original sampler process, descendants and streams are positively received and its complete output set is pinned, release that invocation's active execution slot. The next group may then use the same workspace with a disjoint admitted output set, even if the previous result has not yet been adopted or `:receive` acknowledged. Retained result/output obligations do not occupy the execution slot. Reject path overlap with any earlier pinned output and reject a second live execution in that workspace. Independent workspaces retain the configured concurrency bound. Admission uses nonblocking bounded capacity, not an unbounded collection of request threads waiting on the semaphore.

The terminal receipt binds invocation, stable control/workspace incarnations, the distinct execution process generation, original request and descriptor digests, exact `SamplerResult`, selected output-set commitment and positive original process/resource receiving. Persist it only after its required output-byte barrier, and before returning it. Only such a receipt permits Review0 to adopt the result as closed execution. A returned failure without positive receiving remains an unresolved invocation; caller-side transport/protocol errors do not manufacture terminal receipts. Current public authentication applies to new execution and full result disclosure; cached descriptor identity does not cache permission.

### Sampler-owned state, capacity and receiving identity

Add one `SamplerInvocationOwner` in `review0_sampler_lib`, supplied to `SamplerHttpBinding` and both concrete sampler application constructors. It owns a dedicated protected persistent `control_root`, an exclusive extension-support owner lock and stable control-allocation incarnation. Keep that lock until original workers and their receivers have actually returned. Use the existing target-support pattern of immutable original/candidate files and a durably selected atomic owner envelope; do not create a recovery database or write the control ledger into the shared output directory. Retain versioned original request/started markers, selected terminal metadata, exact receiver/transfer records and workspace incarnation/retirement markers. The ledger contains metadata and digests, never media payload, raw bearer credentials or receiving secrets.

Normal process restart preserves the control/workspace allocation incarnation and reads original terminal records. Its new process/lease generation is separate and cannot authorize relaunch of a previously started invocation. A new/empty control root or replaced workspace has a new allocation incarnation; an old lookup miss is unresolved, never proof of nonacceptance. Refuse missing/corrupt mandatory owner records and populated incompatible pre-v1 state. Explicit new/empty initialization is the only initialization path; no startup reset or reconstruction of an original worker from a PID.

Add `state init --control-root PATH` to each sampler's existing application CLI, using its owner lock and a current versioned control marker. It refuses populated/unexplained state, creates one new allocation incarnation only in genuinely empty state and returns that nonsecret identity. Review0's required `expected_control_incarnation` is configured from this result before admission; the normal server never silently allocates a replacement. Keep the `GET /v1/sampler` semantic descriptor body unchanged. Operational acceptance/readback envelopes report the retained control incarnation, and every caller compares it to its accepted/configured binding. The target creates the workspace-incarnation marker under its existing protected workspace owner before the first sampler submission; neither process may replace it while originals remain.

Reuse the proposed [`RetainedStateCapacity` owner][retained-capacity] for control metadata, staged result files, tombstones and reserved cancel/receiving headroom. Require `control_root`, `retained_state_max_bytes`, `retained_state_min_free_bytes`, `review0_registration_id`, active `receiving_key_id` and absolute `receiving_key_file` in both [Opus][opus-app] and [NVENC][nvenc-app] sampler entry points, HTTP constructors and installed manifests. A separate `retained_receiving_keys` list contains unique older `{key_id, key_file}` entries with absolute file paths. `revoked_receiving_key_ids` is the explicit compromise-refusal list; it cannot contain the active key ID. Both lists default to empty for new state. Startup requires every retained key ID to have its exact configured file or explicit revocation; unexplained missing keys cause refusal. Explicit revocation retains all original metadata while disabling only proofs under that ID, so sampler-local receiving remains available. Bind settings through each existing `A_REVIEW0_*_SAMPLER` prefix. The small example uses **1073741824 bytes / 67108864 bytes** only as fixture settings; deployment values are explicit, with no unlimited default. Review0's [`SamplerConfig`][review-http] and client registration carry the matching registration/key fields and expected control incarnation. Existing workspace/payload admission remains independent.

Reserve exact request/control metadata and a conservative bounded next terminal-result/transfer barrier before dispatch. Enlarge that original reservation before accepting a larger result; refusal retains the original bytes and owner. Keep only admitted active execution state in memory; use point-addressable invocation/workspace records and bounded on-disk ownership indexes for output paths and pending transfers. Rebuild capacity aggregates by bounded streaming reads before readiness, not on status calls. Selected or unexplained files retain liability across restart. No number of completed results, empty execution slots or low pending-job count implies free retained-state capacity. The dedicated volume quota is the independent physical bound; reserved headroom keeps original cancellation and receiving operable when new admission is refused.

Private receiving is a **proposed application-specific binding**, not a general authentication subsystem or an exception that trusts an invocation ID. Reuse the current protected secret-file/configuration patterns, `riverhog_canonical_json.canonical_json_bytes`, Python's `hmac`/SHA-256 and `secrets.compare_digest`. Configure a distinct random 32-byte receiving key for each original Review0 registration on the two peers. Its protected secret file contains exactly 64 lowercase hexadecimal characters, optionally followed by one LF, decoding to exactly 32 bytes; raw binary, additional whitespace and other encodings are rejected. Retain only its key ID and registration binding in the accepted envelope. The request and response MAC domains are respectively `review0-sampler-original-receiving-request/v1` and `review0-sampler-original-receiving-response/v1`, separated from the canonical body by a NUL byte. Bind method/path, registration/key ID, control/workspace incarnations, invocation/request digests where applicable, operation, exact acknowledgement digests where present and a fresh 32-byte caller nonce encoded as lowercase hex. The response also binds the request digest and that nonce. Reject unknown fields and noncanonical encodings. The proof itself is neither persisted nor logged.

There is no wall-clock expiry or general nonce-history store: this proof is valid only for the already retained original and its permitted idempotent receiving transitions. Exact mutation replay returns the same selected acknowledgement; a repeated read may report newer bounded receiving facts for that same original. Changed transfer/retirement digests conflict. A retired workspace returns only its exact retained retirement receipt. A new incarnation or another registration cannot reuse the proof. Rotation selects a new receiving key ID for new acceptances; old key files remain available solely for the originals/retirement records already bound to them for the life of that control incarnation. Public bearer rotation/revocation does not remove those keys. Explicit compromise revocation of a receiving key rejects further proofs under it, leaves its originals and liabilities retained, and still permits sampler-local process quiescence. Independently current public authority for the same configured original registration may still reconcile its exact original through the normal operations. Without either valid authority, preserve unresolved custody; do not silently rebind the original to a new key or accept an unverified transfer.

That original proof permits only `:receiving`, cancellation of the same original, exact `:receive` transfer and workspace retirement. It never authenticates `POST /v1/sample`, grants, new workspace allocation, full-result/payload disclosure or an unrelated original. The service verifies the retained accepting registration and binding, not a newly asserted registration or new access under the old public token. A revoked caller can learn only the bounded receiving facts of the original it already owns. If it had not yet received the full terminal result when public authority was revoked, the sampler retains that result/output; fresh disclosure waits for current authority. Local process/stream quiescence and cost receiving still continue. A lost receiving key or unavailable old owner leaves explicit unresolved custody; it does not authorize replacement execution.

The concrete HTTP adapters select this authentication mode only for those declared operations, before their normal current-bearer gate would reject original receiving. Keep the existing configured endpoint/TLS policy; the MAC adds no arbitrary callback or trust in a new server URL. Full-result GET and new acceptance remain behind current public authorization. Export both modes and their exact bounded schemas through `review0_sampler_protocol`, conformance and installed clients; do not implement a permissive fallback in the generic dispatcher.

Review0 first retains the operational invocation beside the original target request, then submits it. On transport loss it keeps the same original, shared workspace, inputs and source reservations, reads back the exact invocation, and requests cancellation when required. It does not re-enter arbitrary sampler code, allocate another invocation ID or release the workspace because a deadline expired. If sampler state is unavailable/corrupt or an old process cannot be positively reconciled, expose pending/refused recovery and preserve the originals. No startup reconstruction of a live process handle from a PID or absent row is permitted.

After durably adopting the exact terminal result and output restart/ownership records, Review0 sends `:receive`; it need not wait for the collection or parent to settle. Review0 then owns the original result/output and all remaining parent/publication obligations. The sampler may compact its transferred invocation to exact identity/terminal/transfer digests only after actual local receiving and this acknowledgement. It never deletes a shared output file merely because transfer occurred. The target releases source/output bytes only under its own shared custody contract. An ambiguous acknowledgement is resolved through exact original readback and cannot trigger another sampler invocation.

After the last group, Review0 durably retains an exact workspace-retirement request and submits it. Compute its invocation/transfer-set SHA-256 by starting with `review0-sampler-workspace-transfers/v1` followed by a NUL byte, then appending each canonical JSON tuple `(invocation_id, request_sha256, terminal_receipt_sha256, output_set_sha256, transfer_ack_sha256)` prefixed by its eight-byte unsigned big-endian encoded byte length, in invocation-ID order. Bind the exact total count separately in the retirement request. The sampler freezes workspace admission, refuses retirement while any execution or transfer is unresolved, and prepares that same complete set in bounded indexed pages outside its control writer. Final acceptance checks the unchanged workspace generation and exact count/digest; it never accepts count alone. No private hashing cursor is durably saved merely because this verification yields.

Then bounded cleanup may collapse invocation tombstones into one compact retired-workspace record retaining the exact retirement request/acknowledgement and set commitment. That record is selected before detailed records are removed; every removed file's exact cleanup remains received through its original owner, with unresolved liability held. A late `:receive` or `:receiving` returns the retained `workspace_retired` receipt. Review0 verifies it against its own retained complete retirement request; it does not infer individual receipt membership from an unknown digest. The exact `:retire` retry returns the same acknowledgement even if the first reply was lost. No post-retirement operation recreates a deleted invocation or returns a vanished full result.

The compact retirement record stays for the life of the control-allocation incarnation and rejects all later submissions for that workspace; its bytes count against retained-state capacity. No timer removes it and no workspace incarnation is reused. This deliberately makes eventual capacity pressure visible rather than inventing proof of downstream archive retirement. It is a closed retention policy, not a requirement for a future general receipt API. No per-file durable cleanup cursor or unbounded history scan is introduced.

The cancellation watcher is an original owned thread: set its stop condition and **join it** before returning from `_sample` or releasing workspace paths. The sampler process/descendant receiver is separate; joining the watcher alone does not close remote execution. During service shutdown, stop admission, request bounded cancellation, receive the originals, then close clients and permit workspace cleanup. Keep unresolved shutdown visible rather than returning the runtime's successful `stopped` result.

This adds no mid-codec resume. An interrupted, positively received attempt with no accepted result may restart from retained input/intent under the original owner's explicit new-attempt rules. Accepted outputs/results are reused exactly. The contract is specific to the existing sampler effect and does not introduce a general workflow service.

## 5. Policy/configuration and state disposition

Review0 and sampler work consume the controller's existing logical-workflow policy/root and bounded child allowance described in [BUDGET.md](BUDGET.md). Server/operator limits remain local clamps; clients cannot enlarge them. No sampler, witness or relay gains an independent 1/8 budget merely by being another process. Verified bounded accounting prefixes can credit completed supported remote computation before its terminal result; they do not prove process/resource receiving. Uninstrumented or waiting tool intervals produce no invented useful credit. Completion, intent/result acceptance, cancellation and actual receiving continue when optional allowance is zero or unknown.

The selected relay/witness paths have no optional computation snapshot capability and create no optional stores in either mode. They retain their mandatory delivery/evidence state; do not add configuration knobs that have no runtime consumer. An expensive indivisible signature/calendar exchange has no fake checkpoint: its exact input and original outcome remain the only supported anchors. Shared Native work reached through Review0 uses the #996 executor and shared policy rather than an application-specific recovery engine.

Update Review0/sampler operational schemas, configuration connections, installed manifests and generated public contracts together for the receiving cut. Existing semantic parameters and source-selection hashes are preserved. The new invocation/state format has no parallel old reader. Before an incompatible application state cut, safely drain what the old owner can finish and preserve its remaining state. The new executable refuses a populated incompatible layout; initialize only genuinely new/empty state through the owner’s explicit state tooling. Do not erase witness evidence, relay cursors, local output or sampler ambiguity to obtain an empty database. Preserve supported forward-upgrade and interrupted-upgrade tests; do not invent an export/transfer facility.

## 6. Decisive evidence

[QUALIFICATION.md](QUALIFICATION.md) specifies the actual commands and integration gates. The unchanged app baseline passed 15 focused tests on clean `c28eceaa…`: relay duplicate/page ordering and independent sources, witness evidence/reset/conflict/nonce preservation, pre-network capacity, statement bytes, Review0 plan/output identity and sampler workspace confinement. It uses fake transports/signers/calendars and a mocked Review0 publication fixture. It does not demonstrate live webhook, calendar, Bitcoin, Minisign binary, actual codec, installed application or full processing lifecycle qualification.

The focused [effects experiment](implementation/effects_experiment.py) additionally tests relay and witness commit-reply loss using actual stores, and compares unchanged empty witness polls against the proposed no-change branch. Each current empty poll writes one progress row in one writer transaction; the proposal makes none while retaining fresh generation/serial checks. A concurrent rebaseline rejects the observation. These are actual SQL statement counters and fixture-port fault witnesses, not physical fsync counts or a measured application speedup.

Required new counterexamples include: webhook acceptance/reply loss and cursor commit/reply loss; held relay thread through shutdown; witness commit/reply loss and stale-result CAS; exact original signature/proof retained after restart; sampler accepted request with lost response, returned result with lost response, client timeout while the real original process remains live, cancellation-watcher delayed write, failed join/close, stale descriptor/authorization, partial or changed output and missing mandatory sampler evidence. Exercise two sequential groups sharing one workspace before parent settlement, held prior transfer acknowledgement, overlapping output refusal, retired-workspace replay, stable control incarnation across restart, replaced allocation refusal, revoked public token with original-only receiving, rejection of that proof for fresh execution/disclosure, and capacity exhaustion with reserved receiving headroom. The new sampler contract must pass the current two-endpoint test’s underlying identity/conformance guarantees while deliberately replacing its obsolete endpoint count. These sampler protocol/capacity changes are proposed obligations; the reference fixtures do not implement or qualify them.
