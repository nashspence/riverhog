# Safety counterexamples and lifecycle growth for the #994 cutover

This is the safety and growth portion of the [#1000](https://github.com/nashspence/riverhog/issues/1000) reference handoff. It selects concrete integration tests and owner boundaries. It does not certify an adaptive implementation: product source remains `c28eceaa2dfec1b3712135469ba12230e74f5ffa`. The current source still persists Native microsteps and has not activated the coupled public protocol proposed by #995–#999.

The governing requirements are [#994](https://github.com/nashspence/riverhog/issues/994), its [scope assignment](https://github.com/nashspence/riverhog/issues/994#issuecomment-6921730895), [AGENTS.md](../AGENTS.md), and the public contracts and actual owner tests linked below. #1000 begins with the real Native → SDK → Core F1 slice. It does not wait for all of #964, reactivate #991, or replace existing qualification with another registry.

## 1. Decisions that the integration agent should implement

1. **Keep mandatory evidence at the smallest boundary that protects its actual counterexample.** Bounded, compatible records can share a transaction. A semantic loop, scheduler yield, elapsed timer, phase label, progress report, or an old test's commit count does not establish a mandatory boundary.
2. **Both recovery modes run the same semantic and effect executor.** `restart` removes only optional recovery publication; it must retain exact input/evidence, random preparation, accepted obligations, provider intentions and outcomes, publication integrity, terminal control, and original receiving.
3. **Optional state never supplies authority.** A corrupt or missing candidate may select a verified older usable generation or replay exact authoritative input. Missing/corrupt original input, history commitment, prepared random bytes, external-effect identity, mandatory result, or current authorization causes explicit refusal. Never manufacture an equivalent-looking replacement under the original identity.
4. **Selection follows complete dependency durability.** The candidate commits its complete semantic state, exact accepted source prefix, child state, source/configuration/algorithm bindings and integrity root before a short, current-authority selector CAS. A cursor alone is insufficient. Retain its predecessor until selection and original dependent receiving are known.
5. **Unknown execution remains owned.** A timeout, canceled future, missing parent row, visible provider object, process exit, or requested close is not proof that the original external call or resource was received. Later compatible observations do not close an original invocation by themselves.
6. **Qualification follows the changed owner.** Move obsolete fault hooks and growth assertions to the new boundaries in the same cut. Preserve each negative control; do not leave the old microstep path enabled merely to satisfy its old tests.

These decisions follow the adopted policies; the tables below make their batching and qualification consequences specific.

## 7. Concrete reference witness and local evidence

It stops immediately after the real source/parent mutation but before commit, or immediately after commit and cache update. The parent checks an exact handshake, sends `SIGKILL`, positively waits for that original process and closes its streams, then opens a fresh Native owner with epoch 1. No external provider or descendant worker is involved.

Before-commit restoration must expose byte cursor 0. After-commit restoration must expose byte cursor 7. Both finish to the same materialized result as direct validation of the original journal. Separate negative controls change source version, current source authority, worker epoch or algorithm and require refusal without changing the original database or reading source payload. An invalid fixture cut is rejected before creating storage. Every returned parent construction is received before the witness succeeds. The test preserves its workspace on failure; its test fixture owns later disposal.
