# Native transition and commit granularity

## Decision: one narrow candidate needs an owning protocol change

The best narrow candidate is **the parent-only promotion from a completed `SemanticFinish` child to `recording`**. The present implementation first commits the child's `done` checkpoint while the parent remains in `finish`; a later public call reloads that child, checks its exact digest, and commits the parent's move to `recording`. This later call performs no further `SemanticFinish.prepare`. Combining only those two publications would be substantially narrower than running multiple semantic phases inside one Native call. [Owning implementation](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_entry_replay.py#L2441-L2497)

**It is not an equivalent bookkeeping edit under the current protocol.** A missing or replaced completed child checkpoint is rejected by the existing next call, but the direct promotion would dispatch the next call to `recording`, which does not read that child. The exact missing contract is **Native completion discharge: when, and on what durable evidence, may an owner stop freshly validating the completed child and its dependent cursor links?** Core must additionally own the mapping of the removed public progress/readiness/adoption/scheduler observation. This reference identifies that gap and stops; it proposes no implementation or commit removal.

Audited source is **d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e**. The [request](https://github.com/nashspence/riverhog/issues/991#issuecomment-6890881026) and [retained one-step Core decision](https://github.com/nashspence/riverhog/issues/991#issuecomment-6889902338) control scope. Product paths in this reference are identical to d4d7. The three-history trace comes from the previously received Native phase reference, **8b639901c4dbe157dce904acec718a23f580c6ca**, whose execution source was **3b47cbba770c31eb1487b50f7e3b16533c10e827**. No new product execution is represented here.

| --- | --- | --- |
| Rows admitted within one Finish scan phase | One phase prepares up to the supplied row budget, charges admitted atom bytes, and may retain a partial cursor when a later atom does not fit. | Already combined, with its present native ordering and budget. |

## Specific counterexample for the one candidate

This is a **static execution-path witness**, not a newly run fault-injection test. Start from an otherwise valid history whose next Finish prepare observes no remaining changed assertion. Hold source, catalog, worker, accepted prefix, predecessor and Core preparation metadata unchanged. Permit the first complete transaction to return. Then delete only the completed row in `journal_semantic_finish`, or replace it so that the exact attempt/binding/header/digest checks fail.

| Step | Current two-call protocol | Direct combined promotion |
| --- | --- | --- |
| First transaction | Applies the final Finish batch and commits parent `phase=finish` with the completed child's identity and digest. | Hypothetically applies that batch and commits parent `phase=recording`, discharging its child reference. |
| Interruption or pause | The committed parent still names the exact completed child. | The parent has already moved beyond the child-validation branch. |
| Child row disappears or changes | Source/worker/prefix/predecessor controls can all remain unchanged. | The same independent controls can remain unchanged. |
| Next public call | `child.load()` rejects a missing exact row or its algorithm/prefix/cursor links; the parent digest check rejects a different child state. No parent promotion is committed. | The `recording` branch checks the effective recorder/context, not the Finish checkpoint. This missing-child mutation alone does not trigger the baseline rejection there; with otherwise valid recording inputs it can reach its next parent commit. |

The rejection is source-explicit: `SemanticFinish._read_checkpoint()` checks the exact row, algorithm, prefix and completed/current/scan links; `_child_step()` also compares its digest with the parent's retained digest. `ValidationLedger._read()` validates parent, prefix and exact predecessor, **not** the Finish table. `JournalStore._check_entry_recording()` resolves only effective recorder/context references. A fresh source or certificate callback does not fill this missing Native dependency check. [Child read](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_semantic_finish.py#L541-L599), [parent dispatch](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_entry_replay.py#L2464-L2497), [ledger read](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_session_checkpoint.py#L485-L541), [recording branch](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_entry_replay.py#L2653-L2673), [recorder check](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/journal_store.py#L1293-L1312).

This proves a change in **fresh rejection and restart behavior**. It does not claim that this fault occurs in ordinary successful execution, that the private database authenticates hostile input, or that the combined version necessarily publishes an invalid final journal. The durable child may eventually be legitimately retired; the current code makes that transition only after the later fresh validation. Moving the discharge point is the owning decision that is missing. `ValidationCheckpoint` does not forbid child fields in `recording`, so a new schema is not established as necessary; an encoding choice alone would not define the missing validation and retirement semantics. [Checkpoint shape](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_session_checkpoint.py#L88-L190)

## Core readiness: the counterexample still limits the design

The ordinary Core unit performs source capture/selection, epoch, topology, union, rank and replay preparation before **one** `owner.advance`. The owner invokes **one** public Native `advance`, then adopts returned progress through its catalog CAS. The outer before/after stamp is evaluated around that complete unit; on an exception there is no after-stamp result. The scheduler may rotate keys and schedule finalization after a progressed unit. [Core unit](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/collection_uploads.py#L2122-L2177), [owner](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/upload_journal_validation_owner.py#L2029-L2122), [scheduler](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/collection_uploads.py#L2209-L2251).

The retained C1 witness is specific: remove the last completed rank `Result` while leaving the rank `Scan` manifest and source/worker controls unchanged. A new Core rank preparation checks that result and fails closed. The ordinary certificate `verify_current()` instead freshly joins manifest/source records; it does not check the `Result` row. Thus a loop that continues Native transitions after the first Core readiness pass can bypass a rejection the next Core unit would make. The maintained graph-marker test expresses this dependency. These separate readiness checks are not an atomic or continuing all-dependency grant. [Rank predicate](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/upload_journal_rank.py#L218-L291), [certificate currentness](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/upload_journal_certificates.py#L735-L751), [maintained witness, inspected only](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/tests/unit/test_journal_epoch_rank.py#L306-L351).

There is an important limit to that argument. The **one narrow candidate** would return immediately after the completed-child promotion and perform no recording work inside that call. Its next actual recording call would still pass the ordinary Core chain. C1 therefore directly refutes a hidden Native loop; it does **not by itself** prove that this immediate-return candidate skips the next recording readiness check. The candidate still removes the old promotion call's distinct readiness/progress/adoption/stamp/finalization opportunity and changes parent versions and hashes. Core must own that observation mapping rather than infer equivalence from equal final semantics. The Native missing-child witness above is the direct counterexample for this exact edge.

## The precise contract required before this candidate can proceed

The missing work is a **Native completed-child discharge contract, reconciled with Core's per-step observation and adoption contract**. Its scope is only the final `finish(done) → recording` promotion. The following are obligations of that one contract, not separate optimization proposals or authorization to implement them.

| Obligation | What the owner must settle |
| --- | --- |
| Completion authority | Identify exactly when the child and its cursor links may cease to be live validation dependencies, and what checked durable evidence supports that discharge after interruption. Preserve or explicitly reconcile the missing/replaced-child witness. A cached success bit is insufficient. |
| Fresh controls | Keep the exact source, source binding, worker epoch, child attempt/binding, accepted prefix and predecessor checks at their owned points. Define the Core dependency/readiness observation for the removed step; Native certificate currentness cannot claim the missing rank predicate. |
| Aggregate admission | Charge the final semantic batch, any completion evidence, repeated metadata and parent publication within the same supplied row/octet allowance, plus an explicit finite transition count. No reset of a row or byte allowance per hidden phase; no payload acquisition before its admission. |
| Transaction and CAS | Define one complete old/new durable state and exactly one parent version increment for the combined unit, while retaining exact child and parent CAS. Simply removing `commit()` or nesting existing helpers is invalid: detached preparation and transaction ownership are explicit. No window may expose child effects without their parent. |
| Partial progress and errors | Specify the durable state and catalog observation if preparation, child application, parent publication, commit or adoption fails. Preserve native diagnostic order. Do not run another phase after a committed unit and then return a capacity/refusal result that conceals that progress. |
| Core adoption and scheduling | Keep per-public-step adoption and real stamp semantics, or obtain a separate owning change. Reconcile the removed observation and resulting version/hash progression, including catalog conflict and finalization opportunities. A publish API that permits monotone jumps is not permission to delay adoption. |
| Terminal and result receiving | This edge is not terminal. It must return before recorder validation, prefix acceptance, terminal transition or result construction. Preserve exact result identity/hash/byte/tail validation and the independent result reader's lifetime. |
| Interruption, restart and originals | Define recovery from the combined commit and from reply/adoption loss, with no replay or loss of committed work. Preserve the original session, storage, workspace lease, construction and borrowed readers until their actual receiving contracts permit release. Timeout or lost reply does not prove worker exit. |
| Growth composition | Reconcile actual child counts and dimensions through Finish, replay, session, owner and Core. One public call must not conceal multiple whole-child scopes or repeated history/resource work. Retain separate metadata widths, indexed populations, correction-wide work and resource custody bounds. |

Current source for these obligations: [budget and byte reservation](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_entry_replay.py#L2230-L2254), [child CAS](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_semantic_finish.py#L798-L822), [parent CAS](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_session_checkpoint.py#L519-L569), [owner recovery and adoption](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/upload_journal_validation_owner.py#L1955-L2122), [custody and receiving](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/riverhog/src/riverhog_core/services/upload_journal_validation_owner.py#L1836-L1953). ## Bounds that must not disappear behind fewer calls

The public work budget admits exact integer rows from 1 through 64, positive work octets, and source octets that fit within work octets. Its default is 64 rows, 33,619,968 work octets and 65,536 source octets. The present phase count is structurally bounded by dispatch: replay selects at most one row, lifecycle, child, graph, recording or publication branch. Finish's scan loop has an explicit row bound and aggregate admitted payload bytes. Empty lookups and phase transitions still perform metadata, decoding, hashing and indexed work. [Public budget](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/journal_session.py#L66-L79), [replay declaration](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_entry_replay.py#L1998-L2188), [Finish scan](https://github.com/nashspence/riverhog/blob/d4d7b6535be2cf491b7859cacea2a9ada4ac8d9e/packages/riverhog-provenance/src/riverhog_provenance/_semantic_finish.py#L672-L730).

The current child and parent already share a transaction. Replacing two committed public observations with one would change protocol work, not merely subtract one driver call. Any future declaration must compose **exclusive parent work plus actual nonoverlapping inclusive child work**, with each child's own input dimensions and admission caps. Do not add inclusive ancestor times, use one unioned population for unrelated child tables, claim that a smaller public-call count proves lower total work, or convert resource retention into execution concurrency. The narrowly selected candidate executes no additional semantic batch; that fact avoids a hidden semantic loop but does not discharge its completion, observation or growth obligations.
